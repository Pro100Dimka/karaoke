# Karaoke Studio — Desktop (Electron + React)

Десктопное приложение поверх backend'а (`backend_update.zip` — распакуй
рядом/поверх своего `backend/`). Устанавливается и запускается как обычная
программа для ПК (Discord-style): один `.exe`/`.dmg`/`.AppImage`,
backend поднимается автоматически при старте.

## ⚠️ Важно перед запуском

Этот код **не был собран и не запускался** в среде, где я его писал (нет
сети для `npm install`). Синтаксис вычитан вручную, структура стандартная
для Vite+React+Electron, но при первом реальном запуске возможны мелкие
нестыковки — если что-то не заведётся, пришли ошибку из консоли, поправим.

## Структура

```
frontend/
├── electron/
│   ├── main.cjs       — окно, запуск/остановка backend'а, IPC
│   └── preload.cjs    — безопасный мост для renderer'а
├── src/
│   ├── api/client.js  — все вызовы к backend (127.0.0.1:8000)
│   ├── components/    — TitleBar, Sidebar, UI-атомы
│   ├── pages/         — все 12 экранов
│   └── hooks/usePolling.js
├── index.html, vite.config.js, package.json
```

## Установка и запуск (разработка)

```bash
npm install
npm run dev:electron   # поднимет Vite dev-server + окно Electron
```

Backend Electron пытается запустить сам (`python run.py` из `../backend`
относительно `frontend/` — см. `resolveBackendDir()` в `electron/main.cjs`,
поправь путь под свою реальную раскладку папок). Если backend уже запущен
отдельно — просто закомментируть `startBackend()` в `main.cjs`.

## Сборка инсталлятора

```bash
npm run build:electron
```

Соберёт через `electron-builder` (`package.json` → `build`) — `.exe`
(nsis) на Windows, `.dmg` на macOS, `.AppImage` на Linux. **Backend в
сборку сейчас НЕ упаковывается** — `resolveBackendDir()` в проде ждёт
python-backend рядом с ресурсами приложения. Для полноценного
"поставил — и просто работает" инсталлятора backend стоит либо:
1) собрать в отдельный exe через PyInstaller и положить рядом, поправив
   `resolveBackendDir()`/команду запуска в `main.cjs`, либо
2) требовать у пользователя предустановленный Python + `pip install -r
   requirements.txt` при первом запуске (проще, но менее "как Discord").

Это осознанно оставлено на следующий шаг — не хотелось гадать, каким
способом ты планируешь распространять программу.

## Что реализовано по-честному, а что упрощено

- **Караоке-плеер** — два синхронных `<audio>` (инструментал + вокал) с
  раздельной громкостью, текст с подсветкой строки, линия мелодии
  (SVG, из `reference.json`). **Сдвиг тональности** сейчас двигает только
  отображаемую линию нот на экране, а не реальный питч звука — честный
  pitch-shift воспроизведения в браузере нужен через DSP-библиотеку
  (SoundTouch-js/Rubberband) и здесь не сделан.
- **Формат lyrics.json/reference.json** — компонент `Karaoke.jsx`
  предполагает `{start, end, text}` / `{start, end, midi}`. Если реальная
  схема AI-пайплайна отличается по именам полей — поправить нужно только в
  `normalizeLyrics()`/`normalizeNotes()` в начале файла.
  
- **Запись голоса** — реальный `sounddevice`-стрим на backend'е, но нет
  предпрослушивания уровня сигнала *до* нажатия "Запись" непрерывно (сейчас
  индикатор уровня обновляется, только когда идёт активная запись).
- **Модели AI** — прогресс скачивания недоступен (Whisper не отдаёт
  процент программно), только статус "скачана/не скачана".
- **Анализ** — показывает то, что реально считает backend (точность,
  отклонение, разбивка по секциям). Дыхание/интонация отдельно и
  "рекомендации" из ТЗ backend пока не считает — это отдельная логика
  поверх `breaths.json`, которую можно добавить следующим шагом.
- **История** — без отдельной таблицы событий, собирается на лету из уже
  существующих записей о песнях/записях голоса.

## Тема/стиль

Цвета и стиль карточек — `src/index.css` (переменные `--accent-1/2`,
`--card-bg` и т.д.), подобраны под референс-скриншот (тёмно-фиолетовый
градиент, полупрозрачные карточки, розово-фиолетовый акцент).
