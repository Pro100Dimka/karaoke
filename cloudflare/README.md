# Онлайн-комната: изменения по аудиту

Сигналинг остаётся в Worker/Durable Object, голос и файлы — WebRTC mesh.
Эти изменения не заменяют аудиодрайвер и не обещают нулевую задержку.

## Поведение

- Поиск, фильтры, радио и настройки караоке доступны всем участникам.
  Сервер допускает только известные пространства UI, сохраняет общий снимок
  и рассылает изменения также отправителю: последние принятые сервером значения побеждают.
- При потере сигналинга клиент пытается восстановить связь до 45 секунд,
  не выключая самостоятельно живой микрофон/WebRTC-поток. У хоста сохраняется
  ID и право владения комнатой. Deadline живёт в Durable Object storage/alarm.
- Явный выход хоста закрывает комнату сразу; обрыв — только после grace-периода.
  Возврат после истечения окна не создаёт комнату заново.
- Передача роли хоста другому участнику намеренно не поддерживается: `hostToken`
  принадлежит создателю комнаты. Если ведущий вышел или не вернулся за 45 секунд,
  комната закрывается и один из участников создаёт новую.
- Автоматическое восстановление относится к тому же запущенному приложению,
  не к его полному закрытию и повторному запуску.
- Восстановление сигналинга не означает возобновление уже оборвавшейся передачи
  файла с того же байта: существующий P2P-протокол требует повторить такую передачу.
- У ICE, heartbeat и команд отдельные лимиты. Превышение отклоняет сообщение
  с видимой ошибкой, не выкидывает всех из комнаты.
- При невозможности установить WebRTC-соединение за 30 секунд или его отказе
  показывается ошибка голоса/передачи песни. Умолчание «участника просто не слышно» убрано.
- Готовые песни скачиваются по Play; скачивание всей библиотеки при входе
  не включено. Существующая автозагрузка после наблюдаемого processing → done сохранена.

## TURN: подготовлено в коде, требует настройки

Для Cloudflare Realtime TURN создайте TURN key в панели Cloudflare и добавьте
два секрета из каталога `cloudflare`:

```powershell
npx wrangler secret put TURN_KEY_ID
npx wrangler secret put TURN_KEY_API_TOKEN
```

Не помещайте эти значения во frontend, `.env` с префиксом `VITE_`, Git или чат.
Worker выдаёт временные credentials только участнику через его WebSocket;
результат кешируется отдельно для каждого участника и не рассылается остальным.
Срок временных credentials — 24 часа. Настройки обновляются при создании новых
peer-соединений; непрерывные сессии более 24 часов здесь не гарантируются.
P2P остаётся предпочтительным путём (не используется `iceTransportPolicy: relay`).
Без секретов работает прежний STUN/P2P; это НЕ означает работающий TURN.

API проверен по [официальной документации Cloudflare](https://developers.cloudflare.com/realtime/turn/generate-credentials/).

## Проверка и выпуск

```powershell
# cloudflare
npm test
npm run check
# front
npx vitest run tests/online-room-recovery.test.mjs tests/online-room-service.test.mjs tests/online-room-context.test.jsx tests/online-room-correlation.test.mjs tests/online-voice-mesh.test.mjs tests/room-contracts.test.mjs tests/room-components.test.jsx tests/online-room.test.mjs
npm run build
```

`room-runtime.test.mjs` использует настоящий локальный Workers runtime и WebSocket:
общие настройки от гостя → обрыв хоста → возврат с тем же ID и снимком → явный выход.
Unit-тесты отдельно покрывают таймауты, истечение grace-периода, сохранение в storage,
отмену reconnect, приватность TURN, ошибку первоначального ICE и всплески сообщений.

Для применения нужны **и обновлённый Worker, и обновлённые приложения участников**.
`npm run check` — только dry-run, сервер он не обновляет. Публикация — `npm run deploy`.
Смешанные старые и новые клиенты не гарантируют общий контроль: старый клиент
по-прежнему отбрасывает гостевые UI-команды. Внешний сервер этой задачей не публиковался.

Перед выпуском на реальных двух ПК проверить:

1. Гость меняет поиск, фильтры, радио, темп и тональность; остальные получают значения.
2. Прервать сеть хоста на 5–10 секунд и восстановить: та же комната/ID, без ручного входа.
3. Не восстанавливать связь более 45 секунд: гости получают понятное закрытие.
4. Нажать «Выйти»: немедленное закрытие, без автоматического входа обратно.
5. После настройки TURN проверить строгий NAT/запрет прямого UDP и наличие
   relay-кандидата в выбранной ICE-паре; затем передачу песни и слышимость обоих голосов.
6. Проверить субъективную задержку и звук на обоих ПК: локальные тесты этого не измеряют.

Полный frontend suite на момент изменения не зелёный: отдельно остаются три
ошибки тестов UI библиотеки и неразрешаемый импорт `songs-grid/results` в
`library-file-picker.test.jsx`. В рамках аудита комнаты эти файлы не менялись.
